# Додавання нових питань за категоріями

Робочий файл — `archive/QUESTION_BANK.md`. Затверджені нові записи додаються в розділ «Нові затверджені питання» перед тематичним покажчиком, під заголовком своєї теми. Архівний початок і знімки проведених ігор не переписуються. Чернетки й шаблон нижче не є затвердженими питаннями.

| `themeId` | Основна тема |
|---|---|
| `cinema` | Кіно, серіали та анімація |
| `music` | Музика |
| `technology` | Ігри та технології |
| `internet` | Інтернет і меми |
| `science` | Наука та природа |
| `world` | Історія та географія |
| `culture` | Культура, спорт і суспільство |
| `logic` | Логіка та числа |

Тема визначається змістом факту. Фото/аудіо/відео — формати, а «Сюрприз» — назва старої категорії; вони не визначають основну тему. Окрема `category` описує підкатегорію, наприклад «Астрономія», «Футбол» чи «Українська музика». Якщо питання перетинає теми, оберіть основну за тим, про що запитується; додаткові пояснення можна зберегти в записі.

## Порядок

1. Перевірити факт, еталонну відповідь, джерело й необхідні медіа. Перевірити поточний банк та решту нового набору на точні й змістові повтори, не лише текстовим пошуком.
2. Отримати затвердження питання в межах поточного запиту/розмови; чинне явне затвердження повторно не перепитувати. Непогоджена чернетка не стає затвердженим записом.
3. Одразу записати повний текст/відповідь, унікальний ID, тему, підкатегорію, роль, дату, статус, джерело та результат перевірки схожості. Для основного поля потрібні рівень 1–5 і базова ціна. Для класичного/стартового/фінального/глядацького рівень може бути `null`.
4. Виконати `node scripts/build-question-topic-index.js` і `node scripts/build-question-topic-index.js --verify`. Нові записи автоматично включаються в покажчик своєї теми, без копіювання в незмінний архів.
5. Перевірити відповідність ролі/формату потрібному режиму. Основні записи з рівнем потрапляють у тематичні пули поля. Сумісні текстові `main`/`final`/`classic` потрапляють у класичний пул. Старт/фінал використовуються відповідними етапами. Глядацькі й вкладені питання лишаються своїми ролями; окремий запис не перетворюється на основну клітинку.

Перевірка полів не підтверджує правильність факту або відсутність перефразованого повтору. `similarity.result`: «суттєвих збігів не знайдено» з порожнім `matches`, або «схоже» / «точний повтор» із початковими ID й поясненням `note`. Для свідомого точного повтору потрібен запис про вже отримане погодження в `reuseApproval`. Однакова відповідь на різні факти сама по собі не є повтором.

## Шаблон після затвердження

Нижче лише шаблон: замініть усі заповнювачі. Він не додає питання до робочого банку. Рівень 3/ціна 300 наведені для прикладу, їх потрібно визначити для конкретного питання.

````markdown
### Наука та природа

<!-- APPROVED_QUESTION_START -->
```json
{
  "id": "new-YYYYMMDD-001",
  "themeId": "science",
  "category": "Змістова підкатегорія",
  "kind": "main",
  "difficulty": 3,
  "approvedAt": "YYYY-MM-DD",
  "status": "затверджено, ще не використано",
  "source": "ще не призначено",
  "similarity": {
    "result": "суттєвих збігів не знайдено",
    "matches": []
  },
  "payload": {
    "q": "Повний затверджений текст",
    "a": "Повна правильна відповідь",
    "type": "text",
    "value": 300
  }
}
```
<!-- APPROVED_QUESTION_END -->
````

Ролі: `main`, `classic`, `firstTurn`, `final`, `audience`. Для `firstTurn` у payload використовуються `question` і числова `answer`; для `audience` — `q`, `options`, індекс правильної `correct`. Для решти потрібні `q`/`a`, крім батьківського триплета з трьома повними підпитаннями.

У `payload.triplet` кожне підпитання має власні `id`, `q`, `a`, `value`, `similarity`; `themeId`/`category` задаються окремо, якщо відрізняються від батьківських. Так само оформляється `payload.cat`. Дата/статус/джерело успадковуються від батьківського запису. У покажчику кожне вкладене питання має окремий рядок; у грі триплет лишається одним складеним питанням.

Статус «використано» ставиться після підтвердження проведення; до цього — «затверджено, ще не використано». Після призначення додайте шлях джерела/розміщення за тим самим ID. Основні метадані читаються з одного робочого файлу, додаткова копія питання в JSON-реєстрі не потрібна. Після змін коду читача потрібен новий запуск сервера; подальші зміни самих затверджених записів він читає при підготовці наступного набору. Уже створені ігри не змінюються.
