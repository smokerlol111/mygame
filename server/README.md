# Сервер: структура після локального поділу

Стан від 22.11.2026: `server.js` скорочено з початкових 2755 рядків до 11. Він завантажує локальні налаштування й викликає запуск застосунку. `server/app.js` збирає залежності обох режимів; правила гри винесено в окремі модулі. Нових залежностей немає.

| Файл / каталог | Відповідальність |
|---|---|
| `app.js` | Створення Express/HTTP/Socket.IO, зв'язування залежностей і реєстрація обробників; запуск після ініціалізації сховища. |
| `lifecycle.js` | SIGTERM/SIGINT, повідомлення клієнтам і завершення сервера/бота та службових інтервалів. |
| `game-catalog.js` | Читання ввімкнених наборів при старті; вибір гри й даних гри кімнати. |
| `routes.js`, `public-url.js` | HTTP, статичні ресурси, QR, каталог, health-check, API сезонів і публічна адреса з налаштувань/Funnel/запиту. |
| `/api/capabilities` | Публічні можливості саме запущеного процесу; сторінка/локальний launcher перевіряють підтримку випадкового пулу, щоб виявити старий сервер. |
| `rooms/store.js`, `rooms/handlers.js` | Окреме сховище активних кімнат для екземпляра сервера, код кімнати, права HOST, створення, вхід, повернення та вихід. |
| `rooms/network.js` | Синхронізація годинника, мережеві показники та моніторинг підключень гравців. |
| `modes/board/helpers.js`, `control.js` | Скидання питання, черга ходу, завершення клітинки, пауза, аварійні команди, коригування балів і перезапуск гри. |
| `modes/board/timers.js` | Таймери стартового, числового, глядацького та фінального питань, пауза/відновлення. |
| `modes/board/first-turn.js`, `choose-tile.js` | Старт гри, стартове питання, відкриття клітинки й підготовка конкретного формату питання. |
| `modes/board/buzz.js` | Відкриття BUZZ, приймання натискань, визначення відповідача та оцінка звичайної відповіді. |
| `modes/board/special-cells.js`, `special-questions.js` | Розміщення спецклітинок і правила Кота, Дуелі, ВА-БАНКу та триплетів. |
| `modes/board/numeric.js`, `final.js` | Числові відповіді/результати; переходи раундів, фінальні ставки, відповіді та бали. |
| `modes/board/media.js`, `state.js` | Поетапне відкриття медіа/переходи результатів; публічний стан нинішнього режиму. |
| `modes/board/random.js`, `random-generator.js` | HOST-підготовка випадкового поля з темами/рівнями, приватні прев'ю та збереження набору в пам'яті для кімнати. |
| `question-bank/catalog.js`, `classification.js`, `approved.js` | Архівні й нові затверджені питання/ID, вісім спільних тем, перевірка метаданих та повний покажчик із вкладеними питаннями. |
| `modes/classic/` | Власні сесії, пул питань, серверний відлік 60 секунд, відповіді капітанів, ручне оцінювання та приватні стани. |
| `audience/handlers.js` | Вхід глядачів, відповіді, глядацькі раунди та відкриття переможців. |
| `seasons/handlers.js` | Адміністрування сезонів, збереження/виправлення результатів, Wild Card і церемонія. |
| `features/media.js`, `themes.js` | HOST-команди аудіо/відео, звукові сигнали та зміна теми. |
| `features/discord.js` | Живий стан Discord-інтеграції, IPC, підсвітка говоріння, запуск/зупинка бота й HOST-команди. |
| `transport/publish-state.js` | Розсилання стану, окремих HOST-секретів і повідомлень про підключення. |

Модулі отримують залежності через аргументи й не імпортують точку запуску. `app.js` створює один набір кімнат, функцій стану, таймерів та Discord-інтеграції для екземпляра сервера. `createApplication()` не слухає порт, не запускає бота й не встановлює обробники сигналів процесу; ці дії виконує `startApplication()`. Каталог читається при створенні застосунку; адреса з файлу Funnel, як і раніше, перечитується під час HTTP-запиту.

Існуючі правила, усі 87 Socket.IO-подій, HTTP-адреси та формат повідомлень старої гри збережено. Додано 18 подій `classic*`, дві події підготовки випадкового поля та окремі сторінки. Обробники старої гри отримують `getBoardRoom`, тому не застосовують свої правила до класичних кімнат. Публічний стан вибирається за типом кімнати. Таймери старої гри залишають свої поточні правила, включно з фінальним двосекундним вікном приймання відповіді після видимого нуля; класичний квіз закриває приймання рівно після свого серверного відліку. Для перевірки таймерів можна передати керований годинник; у звичайному запуску використовується системний.

`storage.js` та `voice-bot/bot.js` залишаються на попередніх місцях. Вміст наборів питань, медіа й версію релізу не змінено; HTML/CSS доповнено окремими екранами нового режиму та входом із меню. Дані активної кімнати, як і раніше, живуть у пам'яті процесу; модульний поділ не додає їхнього відновлення після перезапуску.

Класичний квіз реалізовано окремо в `modes/classic/`; [інструкція, формат набору та межі першої версії](modes/classic/README.md). Один пристрій капітана на команду, одна остаточна відповідь на питання з автоматичним здаванням чернетки, пауза, ручне зарахування, окремі таблиці після третин, фінальне відкриття місць і JSON результатів. Набір завантажується ведучим у пам'ять; нових затверджених ігрових питань цей етап не додає.

Перевірки в `tests/ai_repro/` використовують випадкові локальні порти й тимчасові дані, без користувацького `.env`, виробничої БД та живого Discord. `server_registration_regression.js` перевіряє повноту й одноразову реєстрацію 87 старих, 18 класичних і 2 подій підготовки поля, незалежність кімнат/ключів/Discord-стану та відсутність запуску при конструюванні. `classic_quiz_regression.js` перевіряє правила з керованим і справжнім годинником; `classic_random_pool_regression.js` — випадковий пул з незмінного архіву й приватність; `classic_ui_regression.js` — цикл HOST/капітан/OBS у справжньому headless Edge. `board_random_regression.js` і `board_random_ui.js` перевіряють тематичне випадкове поле та його HTTP/HOST/PLAYER/OBS. Тести тем, таймерів, черги ходу, спецпитань та IPC імпортують відповідні модулі замість вирізання їхнього тексту з `server.js`.

Історичні аудити та їхні посилання на рядки старого `server.js` залишаються прив'язаними до своїх SHA. Їхні діагностичні сценарії не є набором перевірок приймання цього поділу; актуальні результати наведено в `CHANGELOG.md`.

Після архівування 22.11.2026 робочий `games/index.json` не містить активних наборів: HOST показує повідомлення про архів і залишає керування сезонами. Запит явно вимкненої гри відхиляється, навіть якщо згодом додано інший активний набір. `loadGameCatalog` приймає шлях до індексу через `GAMES_INDEX_FILE`; JSON наборів читаються поруч із цим індексом. У звичайному запуску використовується `games/index.json`. Ізольовані регресії використовують незмінний архівний індекс, а окремий `archived_games_regression.js` перевіряє справжній порожній каталог і новий активний набір у тимчасовій копії.
