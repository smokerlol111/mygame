# Правила роботи з репозиторієм

- На початку задачі прочитай `CHANGELOG.md`, особливо «Правило подальшого ведення».
- Для кожної погодженої зміни оновлюй `CHANGELOG.md`: дата, файли, функціональний ефект, вплив на HOST / PLAYER / OBS / сервер / дані та фактично виконані перевірки.
- Перед завершенням коміту/пушу звір журнал із Git: застосовані зміни мають бути описані з точними SHA. Якщо SHA функціонального коміту став відомим лише після його створення, додай його окремим комітом документації. Самопосилання на SHA цього документарного коміту не потрібне.
- Окремо зазначай погодження, внесення до `main`, деплой і тестування. Не називай пуш деплоєм, а ізольовану перевірку — тестом на реальних телефонах чи OBS.
- При зміні контрольної точки журналу синхронізуй посилання на неї на початку `README.md`.
- Не присвоюй новий номер релізу без підтвердження власника.
